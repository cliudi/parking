## Стабильность

- Основные парковки загружаются отдельно от дополнительных условий.
- Добавлены состояние загрузки и кнопка повторения после ошибки.

- Пустые координаты больше не превращаются в 0,0.
- При недоступности уличного RPC сохраняется предыдущая успешная геометрия,
  но показываются лишь записи из нового опубликованного списка парковок.

## Покрытие улиц

Новая отдельная таблица street_coverage_segments. Не изменяет parkings и не
объявляет парковку разрешённой. Доступ на чтение через RLS только администраторам;
запись только через защищённые RPC. Прямые INSERT/UPDATE/DELETE закрыты.

path использует [lat,lng], как существующий редактор; geometry — PostGIS
LineString SRID 4326, создаётся серверной функцией в правильном порядке [lng,lat].
Статусы: parking_added, no_parking, partial, recheck. Есть сторона, комментарий,
необязательный район, отдельная фактическая дата проверки. Для завершённых
проверок дата обязательна. updated_at не заменяет checked_on.

Редактор: просмотр по умолчанию, создание, продолжение кликами, перетаскивание
вершин, вставка изгиба, удаление вершины, разворот со сменой left/right,
сохранение, удаление с подтверждением. Версия записи предотвращает потерю чужих
изменений при одновременной работе. Несохранённые изменения требуют подтверждения.
Статусы фильтруются, парковки отключаются. Секция сохраняется через #coverage.
Линии покрытия пунктирные, отличимы от сплошных парковочных линий.

## Поиск по адресу назначения

- Главная «Куда вы едете?», история запросов, «Рядом со мной».
- Адресный поиск возвращает до 8 вариантов; пользователь выбирает конкретный.
- Поиск парковок отдельным публичным запросом вокруг выбранного адреса.
- 300/500/1000 м: один запрос 1 км, показ наименьшего непустого радиуса.
- Для уличных объектов — расстояние до ближайшей точки линии.
- Расстояние явно обозначено как прямое, не пеший маршрут.
- Результаты независимы от фоновой загрузки карты/GPS, поздние ответы отменяются.
- Отдельные состояния ошибки, пустой выдачи и недоступных дополнительных данных.
- Кнопки маршрута и деталей используют существующие функции Parky.
- Из карточки выбранной точки карты можно искать парковки рядом с ней.
- RU/UZ/EN для новых основных подсказок.

Edge parkly-geocode расширен режимом search-address без изменения reverse API.
Существующий YANDEX_GEOCODER_API_KEY с разрешения владельца сохранён в Supabase.
Но проверка выявила ограничение ключа: с Referer сайта он работает, без него
Яндекс возвращает 403. Ограничение не обходили. Поэтому frontend использует
сначала браузерный HTTP-геокодер с настоящим Origin/Referer сайта, затем Edge как
резерв. Серверный адресный поиск пока возвращает search_not_configured; для
него нужен разрешённый серверный ключ. Reverse API имеет прежние браузерные
fallback-механизмы; прямая серверная проверка также не дала адрес.
Поддержка необязательного YANDEX_SEARCH_API_KEY в режиме search подготовлена,
но пользовательский интерфейс этот режим НЕ вызывает.

## Готовое покрытие на карте черновиков (добавление 27 сентября)

По уточнению владельца «готовая улица» в этой функции — сохранённый участок
из «Покрытие улиц», а не опубликованная парковочная линия.
На карте черновиков добавлен отдельный включённый по умолчанию слой:

- Только parking_added/no_parking с датой проверки и корректной геометрией.
- Сплошная линия шириной 10 px и strokeOpacity 0.5 (прозрачность 50%).
- Зелёный: парковки внесены. Синий: проверено, парковок не найдено.
- Не зависит от фильтров парковок, включая «Только черновики».
- Галочка позволяет скрыть слой; настройка сохраняется в этом браузере.
- Соседние линии одного статуса соединяются визуально только при точном
  совпадении концов. Нет соединений через промежутки или произвольных ветвей
  на перекрёстках. Одинаковые пути, включая обратный порядок, рисуются один раз.
- Объединение не меняет записи, сторону проверки, даты или границы в БД.
  Отдельные участки редактируются через «Изменить покрытие».
- Не определяется автоматически полнота всей именованной улицы; отображается
  только сохранённая проверенная протяжённость. Покрытие не разрешает парковку.
- Обновление/возврат на карту перечитывает все страницы данных; при ошибке
  слой очищается с сообщением и повторением, черновики продолжают работать.

Миграция не нужна; используется существующий административный RLS-доступ.
Модуль не подключён к публичному сайту или Mini App.
Уточнение отображения: по умолчанию и после сброса фильтров видны черновики
и опубликованные парковки вместе. Рисунок, размер и обработчики прежних значков
не меняются. Покрытие находится в нижнем слое areas с zIndex -10, не поднимается
при наведении и пропускает клики на карту. Фильтр «Только черновики» по-прежнему
можно выбрать вручную; он скрывает опубликованные парковки, но не покрытие.
Проверка: `node scripts/test-draft-coverage.js`, а также прежние тесты редактора
покрытия и улиц. Карта и API в этих тестах изолированы; production-записей тесты
не создают и не изменяют.
