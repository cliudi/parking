# Этап 4: Parky внутри Telegram

Реализованы оболочка и следующий подэтап: assets/telegram.js и assets/telegram.css.
Подключение SDK только при запуске из Telegram, безопасные отступы, высота окна,
кнопка «Назад», подтверждение выхода из изменённой формы. Токен не используется
в клиентском коде. Проверка: node scripts/test-telegram.js (изолированный SDK).
На реальном телефоне и в опубликованном Mini App этот подэтап ещё не проверен.
Добавлены тема Telegram без перезаписи предпочтения браузера, LocationManager
по явному нажатию (с учётом версии SDK), открытие внешнего навигатора через openLink.
В assets/location.js геолокация переработана: быстрый запрос и точное наблюдение
независимы; поздний грубый ответ не затирает свежий точный. Предыдущая точка
сохраняется в памяти при ошибке с подписью «Последнее известное место».
Сохранённые на диске координаты не восстанавливаются; геолокации по IP нет.
Неточные/устаревшие координаты не используются как точный старт маршрута.
Кнопка ручного выбора + «Я здесь» задают место до обновления страницы/явного
возврата к автоматическому определению. Поздние callbacks ручной выбор не меняют.
Ручная точка подходит для поиска и построения маршрута, но не живого сопровождения.
Устройство может ошибаться даже при малой заявленной погрешности: приложение
не может доказать фактическое местоположение; ручной выбор остаётся доступен.
База Supabase и парковки остаются общими с сайтом.
Сначала адаптируем веб-интерфейс и проверяем запуск; автоматический вход через
Telegram — отдельный последующий этап. Не публикуйте токен бота в чате или GitHub.

## Что сделать владельцу

1. Открыть официального https://t.me/BotFather .
2. Если бот уже существует — использовать его, не создавать дубликат.
   Иначе отправить /newbot, название Parky и свободный username с окончанием bot.
3. Сохранить выданный токен как пароль. Для настройки кнопки через BotFather
   передавать токен ассистенту не требуется. Прислать только @username бота.
4. После адаптации сайта открыть /mybots → свой бот → Bot Settings → Menu Button
   либо команду /setmenubutton. Указать текст «Открыть Parky» и HTTPS-адрес
   https://cliudi.github.io/parking/ . Не указывать admin.html.
5. При необходимости настроить Main Mini App в BotFather, чтобы появилась
   кнопка запуска в профиле. Использовать тот же HTTPS-адрес и фирменный логотип.

Основание: https://core.telegram.org/bots/tutorial#obtain-your-bot-token
и https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button .

## Что сделаем в коде вместе

Статус: SDK, safe-area/высота, Back, тема, LocationManager, внешние ссылки реализованы.
Ссылки на конкретные парковки реализованы следующим подэтапом (см. ниже).
Остались приёмка на реальных устройствах, затем отдельно серверная авторизация
Telegram и обработчик бота/уведомления.

- Подключим Telegram WebApp SDK с безопасным обычным режимом вне Telegram.
- Адаптируем safe-area, высоту окна, клавиатуру, тему и кнопку «Назад».
- Проверим доступ к геопозиции после явного действия пользователя и работу
  без разрешения: поиск по адресу и точке остаётся доступен.
- Проверим браузерный адресный геокодер в Telegram: если WebView не передаёт
  подходящий Referer, сначала настроим серверный ключ, не будем обходить ограничения.
- Проверим загрузку парковок, карты, фотографии, избранное и открытие навигатора.
- Добавим ссылки на конкретные парковки, не требуя переноса записей в другую БД.
- Пока сохраним существующую Supabase-авторизацию для действий с аккаунтом.
- Для ответов бота на /start и уведомлений позже настроим серверный обработчик;
  сама кнопка запуска не означает, что бот уже умеет отвечать на сообщения.

## Проверка перед приглашением пользователей

Открыть из бота на Android и iPhone; проверить клавиатуру, нижнюю навигацию,
светлую/тёмную тему, отказ GPS, адрес в другом районе, построение маршрута,
закрытие/повторное открытие и слабую сеть. Публично показываются только
разрешённые к публикации данные; покрытие улиц остаётся исключительно в админке.

Не считать Telegram-профиль подтверждённым аккаунтом Parky без проверки initData
на сервере. Это будет этап 5, с привязкой к существующему аккаунту и сохранением
избранного. Данные localStorage обычного браузера в Telegram автоматически не переносятся.

Источники: https://core.telegram.org/bots/webapps#designing-mini-apps
и https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app .

## Ссылки на парковки — 27 сентября 2026

Владелец подтвердил, что Main Mini App у @parky_app_bot включён.

- Сайт: `https://cliudi.github.io/parking/?parking=<UUID>`.
- Telegram: `https://t.me/parky_app_bot?startapp=parking_<UUID>`.
- Обрабатываются `tgWebAppStartParam` и `initDataUnsafe.start_param`.
  Последний используется только как непроверенный навигационный параметр,
  не как подтверждение личности. UUID строго проверяется до обращения к API.
- «Поделиться» в браузере передаёт ссылку сайта, в Mini App — Telegram-ссылку.
  Если системное меню недоступно, открывается окно с копированием ссылки сайта
  и кнопкой выбора получателя в Telegram. Сообщения автоматически не отправляются.
- Копирование подтверждается только после успеха Clipboard API; при отказе
  ссылка остаётся доступной для ручного выделения и копирования.
- Загрузка по UUID использует существующую таблицу с публичным anon-доступом,
  RLS, фильтром APPROVED и явным списком полей. Даже с админ-сессией запрос
  не использует её токен. Закрытые объекты и внутренние заметки не запрашиваются.
- Координаты читаются из существующего EWKB Point с проверкой SRID 4326,
  формата и диапазона. Перенос данных и новая миграция не требуются.
- Уличный участок дополнительно проверяется существующим публичным RPC.
- Ошибка сети отличается от отсутствующего/скрытого объекта; есть повторение
  и отмена. Закрытый пользователем экран не открывается поздним ответом.
- Общая загрузка карты не удаляет открытую карточку, полученную по ссылке.
  При поздней загрузке карты она центрируется на парковке. Координаты парковки
  не становятся текущим положением пользователя.
- В ссылки не включаются initData, токены, профиль или геолокация пользователя.

Проверки: `node scripts/test-parking-links.js` с изолированными API и картой;
публичный запрос одной существующей APPROVED-записи успешно проверен чтением.
Реальный переход по Telegram-ссылке между двумя устройствами требует приёмки.
Документация формата: https://core.telegram.org/bots/webapps#launching-the-main-mini-app .

Следующий блок (ещё НЕ реализован): проверка подписи и срока initData на сервере,
вход/явная привязка Telegram к существующему аккаунту без потери избранного.
После этого — обработчик /start и добровольные уведомления о модерации.
Текущий этап не создаёт пользователей, не связывает аккаунты и не меняет секреты.

## Fullsize и ручной полный экран на компьютере

Пользователь переключил запуск в BotFather с Fullscreen на Fullsize.
Настройка запуска не меняется кодом: `expand()` разворачивает Mini App внутри
обычного окна, `requestFullscreen()` при запуске не вызывается.
На Telegram Desktop/macOS и настольном Telegram Web добавлена верхняя панель
«На весь экран» / «Выйти из полного экрана». Для мобильного Mini App и обычного
сайта она не создаётся. Панель занимает отдельное место над содержимым.

Используется Telegram API 8.0 с событиями fullscreenChanged/fullscreenFailed.
Состояние кнопки определяется реальным состоянием API, а не фактом нажатия.
Есть блокировка повторного нажатия до ответа и ограничение ожидания в 5 секунд.
Если клиент сообщает UNSUPPORTED, возможен браузерный Fullscreen API по новому
явному нажатию; при отсутствии поддержки показывается подсказка развернуть
само окно. Размеры карты и безопасные отступы пересчитываются при переключении.

Проверка: `node scripts/test-telegram-fullscreen.js` — вход, выход, внешнее
изменение состояния, UNSUPPORTED, исключение, тайм-аут, старый SDK, браузерный
резерв, ширины 320/480/1440 и отсутствие кнопки на телефоне/обычном сайте.
Эти тесты используют имитацию SDK; работу системного окна Telegram на компьютере
владельца нужно подтвердить отдельно.
Основание: https://core.telegram.org/bots/webapps#initializing-mini-apps .
